# CLAUDE.md

## Project Overview

PrimeForm is an AI-powered fitness app designed for women, built by KineticIQ. It features cycle-aware training, post-partum recovery guidance, AI-generated nutrition/workout plans, and daily tracking.

## Tech Stack

- **Framework:** Flutter (Dart), SDK ^3.10.4
- **State Management:** Riverpod (`flutter_riverpod`)
- **Local Database:** Isar 3.x (with `isar_flutter_libs` vendored at `vendor/isar_flutter_libs`)
- **Backend:** Firebase (Analytics, Cloud Functions, Firestore)
- **Notifications:** `flutter_local_notifications`
- **Theme:** Material 3 with custom warm beige/sage green design system (`lib/theme/app_theme.dart`)

## Commands

```bash
# Install dependencies
flutter pub get

# Generate Isar model code (required after model changes)
dart run build_runner build --delete-conflicting-outputs

# Run the app
flutter run

# Run tests
flutter test

# Static analysis
flutter analyze
```

## Project Structure

```
lib/
  main.dart              # App entry point, routes, Firebase init
  db/isar_db.dart        # Isar database singleton
  data/                  # Static data (exercise alternatives)
  models/                # Isar collection models (with .g.dart generated files)
  repos/                 # Data access layer (PrimeRepo, UserProfileRepo)
  screens/               # All app screens
  services/              # Business logic services (notifications, analytics, food API, steps)
  state/providers.dart   # All Riverpod providers (single file)
  theme/app_theme.dart   # Design system colors, theme, styles
  utils/                 # Utility calculators (cycle, postpartum)
  widgets/               # Reusable widget components
```

## Architecture & Patterns

- **State:** All Riverpod providers are defined in `lib/state/providers.dart`
- **Data flow:** Screens -> Providers -> Repos -> Isar DB
- **Database:** Isar collections defined in `lib/models/`. After changing a model, regenerate with `dart run build_runner build --delete-conflicting-outputs`
- **Generated files:** Files ending in `.g.dart` are auto-generated by Isar. Never edit these manually
- **Routing:** Named routes defined in `main.dart` (e.g., `/home`, `/onboarding`, `/plan`)
- **Entry flow:** SplashScreen -> AppInitializer checks for UserProfile -> OnboardingScreen or AppShell

## Isar Models (Collections)

- `UserProfile` - User data, goals, cycle info, injuries
- `PrimePlan` - AI-generated nutrition plans
- `WorkoutTemplateDoc` - AI-generated workout programs
- `WorkoutSessionDoc` - Individual workout session records
- `CheckIn` - Daily check-in logs (weight, mood, energy, steps)
- `MealLog` - Meal entries with macro breakdowns
- `FoodItem` - Cached food database items

## Design System

- **Background:** Warm beige `#F5F0E8`
- **Primary accent:** Sage green `#8BA888`
- **Macro colors:** Protein green `#4CAF50`, Carbs yellow `#E5B94D`, Fat pink `#E57373`
- **Cards:** White with 16px border radius, subtle shadow
- **Buttons:** Rounded (24px radius), sage green primary
- **Use `AppColors` and `AppStyles`** from `lib/theme/app_theme.dart` for all styling

## Conventions

- Use Riverpod for all state management; add new providers to `lib/state/providers.dart`
- Screens go in `lib/screens/`, widgets in `lib/widgets/`
- Use the existing repo pattern (`PrimeRepo`, `UserProfileRepo`) for data access
- Follow Material 3 conventions with the custom `AppTheme`
- Use `ConsumerWidget` / `ConsumerStatefulWidget` for widgets that need Riverpod state
- Prefer `autoDispose` providers where appropriate to avoid memory leaks
- Women's health features (cycle tracking, postpartum) are a key differentiator - maintain and respect these
